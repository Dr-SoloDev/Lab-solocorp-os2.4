# D1 — Local Synthetic Media Rendering for Content MCP

**Date:** 2026-10-30
**Status:** Draft; pending independent review
**Owner:** Content Creator / Engineering boundary
**Supersedes:** No prior bridge result; extends `D1-content-ffmpeg-integration.md`

## 1. Work

Add `render_campaign_media_local(campaign_id)` to Content MCP. It turns a
six-scene, 90-second stored storyboard into a local Thai voice draft, original
synthetic scene frames, captions, and a validated MP4 under
`central_bus/content/`. It appends a truthful local-CLI execution record and
requests the existing Publish Gate. It does not publish or approve.

## 2. Why an agent

The work crosses Python MCP schemas, versioned Bus manifests, locally installed
TTS, Node/Three.js frame generation, FFmpeg execution, asset rights, and human
approval. A client agent can wire these installed engines into one reproducible
campaign workflow while keeping the existing MCP-result contract distinct.

## 3. Agent, tools, and scope

- Implementer: Codex in the repository workspace.
- Tools: Content MCP/service, Piper CLI, Three.js/Playwright/Chrome, FFmpeg CLI,
  ffprobe, and isolated synthetic tests.
- Files written by the renderer must resolve under
  `central_bus/content/local_media/<campaign>/<job-id>/`.
- Only frames and audio generated by the local pipeline may be passed to the
  current FFmpeg runtime. Real user media remains blocked pending an
  independent security/runtime verification.
- Piper `th_TH-tsync2-medium` is CC BY-NC-SA 3.0 non-commercial. Generated
  voice stays a rights-unverified internal draft unless a cleared model is
  supplied. Publish Gate and human approval remain mandatory.
- Concat is absent. FFmpeg Direct CLI is the documented fallback.

## 4. Definition of success

1. MCP exposes the local render tool and validates the storyboard before work.
2. A real local run writes a 90-second 1080x1920 H.264/AAC MP4, and ffprobe
   confirms dimensions, duration, frame rate, and audio.
3. Campaign assets record `ffmpeg-cli`, `in_progress`, completion/failure,
   output hash, and rights status without fabricating an FFmpeg MCP response.
4. The Publish Gate remains `review_required`; no human approval or publication
   occurs during rendering.
5. Independent review and D3 evaluation remain open until evidence is attached.
