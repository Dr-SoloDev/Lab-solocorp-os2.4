## 3. กฎของครอบครัว

1. **โค้ดขึ้นแกนกลาง · อัตลักษณ์แยกสาขา**
   ชื่อหัวหน้า · ชื่อ Owner · โครงสร้างแผนก · สิ่งที่ปิด → ของ instance นั้น
   bug fix ของระบบกลาง · skill ที่ทุกคนใช้ได้ → ขึ้นแกนกลาง
2. **PR กลับมาต้องแยก 2 ส่วน** — ส่วนโค้ด (merge ได้) กับส่วนอัตลักษณ์ (ไม่ merge)
3. **ผู้ผลิต ≠ ผู้ตรวจ** — งานที่ instance หนึ่งทำ อีก instance ตรวจ (ดู [`SOP-06`](../sop/SOP-06-certification.md))
4. **หลักฐานคือของจริงเสมอ** — output + exit code + ไฟล์ที่ได้ · ไม่มีหลักฐาน = ยังไม่ผ่าน
5. **ไม่มี instance ไหนต้องเหมือนกัน** — ต่างได้ ขอแค่ทำงานได้จริงและรับผิดชอบผล

## 4. ช่องทางสื่อสารข้ามครอบครัว

> ต่าง instance ไม่มี Central Bus ร่วมกัน → **GitHub คือ bus ข้ามบ้าน**

| ทิศทาง | ช่องทาง | Label |
|:--|:--|:--|
| แกนกลาง → พี่น้อง | เปิด Issue ใน upstream ระบุชื่อผู้รับ | `dispatch:to-sister` |
| พี่น้อง → แกนกลาง | เปิด PR กลับเข้า upstream | `dispatch:from-sister` |
| ทะเบียนสมาชิก | ข้อมูล instance ทั้งหมด | `family` |
