# กวี — Narrative Draft
Campaign: solocorp-model-health-90s-20261030
เป้าหมาย: ทำให้ผู้สร้าง agent เปลี่ยนจากการเชื่อสถานะ success ไปสู่การตรวจผลเรียกโมเดลจริง

## Hook ที่เลือก
หน้าจอขึ้นสีเขียว แต่ถ้าไม่มีใครตรวจว่าโมเดลตอบจริง เรารู้ได้ยังไงว่างานยังเดินอยู่?

## เรื่องเล่า
ในบันทึกงานภายในของเรา เคยพบชื่อโมเดลที่เรียกใช้ไม่ได้สองรายการ แต่ระบบยังรายงานว่าสำเร็จ เรื่องนี้ยังเป็นข้อมูลภายในที่ต้องตรวจหลักฐานเพิ่ม จึงไม่เล่าเหมือนเป็นสถิติของทั้งวงการ
ปัญหาที่คนสร้างระบบควรจำคือ สถานะจาก orchestration เพียงอย่างเดียวไม่ยืนยันว่า endpoint ตอบกลับหรือ agent ทำงานครบ
ให้ตรวจชื่อ provider และ model ที่ตั้งไว้ ทดลองเรียกจริง เก็บผลตอบกลับและ exit status แล้วแจ้งเตือนเมื่อ health check ล้มเหลว
เป้าหมายการออกแบบของเราคือรู้ความผิดปกติให้เร็ว โดยตั้งกรอบแจ้งเตือนไม่เกินหกชั่วโมง ทั้งนี้ไม่ใช่ SLA ที่รับรองว่าเปิดใช้แล้ว

## จังหวะการเล่า
1. ตั้งคำถามด้วยหน้าจอเขียวที่ชวนสงสัย
2. เปิดเผยเหตุการณ์ภายในโดยระบุว่าเป็นบันทึกที่ยังไม่ยืนยันอิสระ
3. แยกคำว่า “ระบบรับงาน” ออกจาก “โมเดลตอบจริง”
4. สาธิตหลักฐานที่ต้องเก็บ: provider, model, request, response และ exit status
5. อธิบายเป้าหมายตรวจจับและแจ้งเตือนภายในหกชั่วโมง โดยเรียกว่าเป้าหมาย
6. ปิดด้วย checklist ที่ผู้ชมทำซ้ำได้

## ประโยคปิด
อย่าหยุดที่คำว่า success — ลองเรียกจริง เก็บหลักฐาน แล้วค่อยเชื่อผล
