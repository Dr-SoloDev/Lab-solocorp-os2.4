# SoloCorp OS: OS สำหรับทีม AI ที่ทำงานเหมือนองค์กรจริง

## ปัญหา

การใช้ AI agent หลายตัวในงานจริงมักจบด้วยความโกลาหล: ทุกตัวพูดข้ามกัน, งานซ้ำ, และไม่มีใครรับผิดชอบผลลัพธ์สุดท้าย SoloCorp OS แก้ด้วยการจัดโครงสร้าง agent เป็นองค์กรที่มีสายบังคับบัญชาชัดเจน

## หลักการออกแบบ

1. **สายการบังคับบัญชา 5 ระดับ** — Owner ตัดสิน vision เท่านั้น, CEO ตัดสินกลยุทธ์, COO เป็น gatekeeper, หัวหน้าแผนก delegate, specialist ลงมือ หัวหน้าไม่ลงมือเขียนโค้ดเอง และ specialist ไม่คุยข้ามแผนกโดยตรง
2. **Central Bus** — ข้อมูลและงานไหลผ่าน bus กลางเท่านั้น ทำให้ตรวจสอบย้อนหลังได้ว่าใครส่งอะไรให้ใคร
3. **SOP > Memory** — ระบบอ่าน SOP แทนการจำ เพราะความจำของ agent เสื่อมได้ แต่เอกสารตรวจสอบได้
4. **Maker ≠ Checker** — งานที่อ้างว่าเสร็จต้องมี checker ต่างคนตรวจพร้อมหลักฐาน สถานะเริ่มต้นคือ NOT PASSED จนกว่าจะแนบ evidence

## ข้อจำกัดที่ยังไม่แน่นอน

- ยังไม่รู้ว่า OpenCode E2E จะผ่านหรือไม่: ปัจจุบัน OpenCode API ปฏิเสธ request ด้วย HTTP 400 (`unsupported_parameter`) ก่อนถึง MCP tool สาเหตุและทางแก้ยังรอตรวจสอบเพิ่ม
- ตัวเลข coverage 75.4% มาจากรอบตรวจครั้งเดียว ยังไม่ได้พิสูจน์ว่าเสถียรข้ามรอบ
- ผลทดสอบ 22 tests เป็นข้อมูล ณ วันที่ตรวจล่าสุด ไม่ใช่คำสัญญาสถานะปัจจุบันของ working tree

## ทำไมสำคัญ

บทเรียนที่แพงที่สุดของระบบ agent คือการรายงานว่า "เสร็จแล้ว" ทั้งที่ไม่มีโค้ดเปลี่ยนแม้บรรทัดเดียว ระบบ certification ladder แบบ D1–D4 บังคับให้ทุก claim มีหลักฐานที่คนอื่นทำซ้ำได้ ซึ่งเป็นสิ่งเดียวกับที่งานวิศวกรรมจริงต้องการ

## สรุป

SoloCorp OS ไม่ได้พยายามทำให้ AI ฉลาดขึ้น แต่ทำให้ทีม AI มีวินัยขึ้น และวินัยคือสิ่งที่แยก prototype ออกจากระบบที่ใช้งานจริงได้

## คำถามเปิด

ถ้า checker ต่างคนคือกฎ แล้วใครควรเป็น checker ของตัว checker เอง — และเส้นแบ่งระหว่าง "ตรวจซ้ำจนเปลือง" กับ "ตรวจน้อยจนพลาด" อยู่ตรงไหน?
