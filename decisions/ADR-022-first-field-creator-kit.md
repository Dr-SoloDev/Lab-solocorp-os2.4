## บริบท

vision §5.2: *"สนามแรกหมุด 4 — ครีเอเตอร์สายสร้างตัวตน (Owner เลือก)"*
→ หมุด 4 = พิสูจน์คุณค่ากับคนตัวเล็ก วัดได้เป็นตัวเลข

หมุด 1–2 มีแล้ว (ADR-019/020 ทำให้เครื่องจักรกลาง + องค์กรเสมือนใช้งานได้จริง)
หมุด 3–5 รอสนามแรกบอก → **นี่คือรอบที่สนามแรกเริ่มต้นจริง**

### กระบวนการที่ใช้ (ไม่ได้คิดเอง — มาจาก vision เอง)

vision §5.4 + กรอบ 1 (เดาแล้วแก้ได้):
1. ถามเบา 3–4 ข้อ → ระบบเดาโครงแรก
2. โชว์สิ่งที่เดาเป็นภาษาคน + ให้แก้ได้ใน 1 แตะ
3. ถามเช็ก "ตรงไหม?" 1 รอบเสมอ (เจ้าของนิ่ง/ข้าม = red flag ไม่ใช่ consent)
4. แล้วค่อยวางเป็น "สนามฟุตบอล" ให้เจ้าของลากเข้าออกเอง

## คำตอบ 4 ข้อ (Owner เลือก 2026-10-20)

| คำถาม | คำตอบ | ผลต่อโครง |
|:--|:--|:--|
| ช่องทาง | **X (Twitter)** — *เปลี่ยนจาก TikTok 2026-10-20 (Owner มีบัญชี X อยู่แล้ว)* | โพสต์คลิปแนวตั้งชิงรางวัล |
| ตัวตน | **ฟรีแลนซ์/งานอิสระ** | "รอยแผล" = งานที่ทำแล้วเละทิ้งหลายรอบ · คำศัพท์ "งาน/ฝีมือ/ลูกค้า" |
| รอบพิสูจน์ | **30 วัน** | เน้นคุณภาพ · แยก **7 วัน = รอบเรียนรู้** / **30 วัน = รอบตัดสินใจ** (ประนียบกับ vision §5.2) |
| รูปแบบ | **ทั้งคู่ — เริ่ม A แล้วค่อย B** | A = HIT ทีละจ๊อบ (เริ่มได้เลย ไม่ต้อง build) → B = ตั้งระบบให้เดินเอง |

**ขอบเขต:** โพสต์เอง + นับผลเอง
**ความเสี่ยงที่ยอมรับ:** เตรียมเป็น **draft** + คนกดยืนยัน 1 คลิก — **ห้าม publish อัตโนมัติ**

## การตัดสินใจ

### 1. แยก "สิ่งที่ต้องตรงเป๊ะ" ออกจาก "สิ่งที่ให้ LLM คิด"

| ส่วน | ใครทำ | ทำไม |
|:--|:--|:--|
| 4 ท่อน · โครงเวลาคลิป · ตลิ่ง 2 ชั้น · แพ็กเกจ | **โค้ด deterministic** (`solocorp_skills/creator.py`) | ต้องตรงทุกครั้ง ไม่ให้ LLM ตัดสินใจเอง |
| ไอเดีย · บท · แคปชัน | **LLM** (ผ่าน skill) | ต้องเป็นของจริง ไม่มีสูตรตายตัว (vision §6) |

### 2. โปรไฟล์ครีเอเตอร์เก็บใน facts store
`creator.<slug>.profile` → ได้ versioning + sensitivity tier + agent ดึงผ่าน `/v1/context` ได้ทันที
(ADR-020 เพิ่ม write channel มาแล้ว — ถ้าไม่มี งานนี้ทำไม่ได้)

### 3. สถาปัตยกรรม 2 ชั้น (จากการเลือก "ทั้งคู่")

| ชั้น | เครื่องมือ | หน้าที่ | login? |
|:--|:--|:--|:--:|
| หาเทรนด์ / อ่านเว็บ | `carbonyl` (47.5MB) | หาข่าว เทรนด์ อ่านเว็บ | ไม่ |
| โพสต์ / นับผล | `stealth-browser` (Chrome) | upload → caption → **save as draft** · อ่าน dashboard | **ต้อง** ครั้งเดียว |

> carbonyl ทำโพสต์ไม่ได้ (ไม่เก็บ cookie) → stealth-browser เป็นตัวโพสต์
> แต่ carbonyl ยังจำเป็นสำหรับ "หาเทรนด์" เพราะไม่ต้อง login และไม่กิน resource

### 4. ความปลอดภัยของการโพสต์ = draft ไม่ใช่ publish
Owner ตัดสินเอง: เตรียมเป็น draft + กดยืนยัน 1 คลิก
→ ถ้า UI เปลี่ยน/ถูกบล็อก ก็พังแค่ก่อน publish ไม่หายจริง

### 5. วัดผลตาม "ตลิ่งคำพูด" ไม่ใช่ยอดขาย
เก่งขึ้น · สม่ำเสมอขึ้น · โอกาสเข้ามา — **ไม่วัด** ยอดไลค์/ยอดขาย/ผู้ติดตาม (หลักข้อ 5 + §5.2)

## ผลกระทบ

**✅ ดี**
- มี "ของจริง" แล้ว: 4 ท่อน + โครงคลิป + แพ็กเกจ 5 ไฟล์ + skill + ADR
- ใช้ของที่มีอยู่แล้วทั้งหมด (facts, web_read, news_daily, stealth-browser, media_pipeline)
- เริ่มใช้ได้ **วันนี้** ในโหมด A — ไม่ต้อง build อะไรเพิ่ม
- North Star filter ผ่านครบ 5 ข้อ (ดู ADR-022 §เหตุผล)

**⚠️ ยังขาด — ต้องหา**
| ขาด | ทำไมสำคัญ |
|:--|:--|
| **ครีเอเตอร์จริง 1 คน** | หมุด 4 ต้องทดลองกับคนจริง (คาเฟ่/ฟรีแลนซ์/ครู/เกษตรกร) — ตอนนี้มีแต่ตัวอย่าง |
| **TikTok account + login** | โพสต์จริงต้องมี account ของครีเอเตอร์คนนั้น |
| **โมเดล B (เวิร์กโฟลว์)** | ยังไม่ทำ — เริ่มจาก A ก่อน แล้วค่อยย้าย |
| **การนับผลอัตโนมัติ** | ต้องมี account ก่อน |

**🚫 ข้อห้ามที่ฝังในตัวเครื่องมือ**
- checklist บล็อกถ้ายังไม่ได้ตั้งตลิ่งโทน 3 คำ
- checklist มีข้อ "ไม่มีคำสัญญาว่ารวยเร็ว/ยอดขาย X เท่า"
- origin log ต้องมีที่มาของภาพ/เพลง/ฟอนต์ทุกชิ้น
- เทสต์ล็อกว่า คำถาม 4 ข้อ ห้ามมีศัพท์เอเจนต์ (vision §6)
