## 1. เจตนารมณ์ตั้งต้น (จาก Owner คำต่อคำ)

**SoloCorp OS ถูกสร้างเพื่อคนตัวเล็ก** — เจ้าของกิจการขนาดเล็ก ฟรีแลนซ์ ครู เกษตรกร คนทำงานสายอาชีพต่างๆ
ให้เข้าถึงระบบการทำงานที่มีประสิทธิภาพได้ โดยไม่ต้องมีทรัพยากร/บุคลากรเท่าองค์กรใหญ่

- SoloCorp เป็น **องค์กรเสมือน** มีแผนก หน้าที่ บริหาร กระจายงาน ประสานงาน อย่างเป็นระบบ
- **ไม่ใช่การแทนที่องค์กรใหญ่** แต่เอากลไกดีๆ ขององค์กรใหญ่มาประยุกต์ให้คนตัวเล็กใช้
- คนตัวเล็กขาดไม่ใช่ความสามารถ แต่คือ **ระบบสนับสนุน** ให้ความสามารถนั้นเต็มศักยภาพ
- เปิดให้ผู้ใช้สร้าง/จัด **Specialist Agents** ที่เหมาะกับอาชีพตัวเอง (บริหาร การตลาด การเงิน ข้อมูล งานเฉพาะทาง)
- ครู เกษตรกร ฟรีแลนซ์ คาเฟ่ ธุรกิจเล็ก — ทุกคนออกแบบระบบของตัวเองได้

## 2. Organizational Core

**CORE PURPOSE** — ทำให้คนตัวเล็กเข้าถึงระบบการทำงานที่มีประสิทธิภาพได้
เปลี่ยนข้อจำกัดทรัพยากร/ระบบบริหาร ให้ออกแบบและจัดการได้ด้วยดิจิทัล + AI Agents

**MISSION** — สร้างระบบองค์กรเสมือนที่ผู้ใช้ปรับใช้กับอาชีพ กิจการ เป้าหมายของตัวเองได้

**VISION** — โลกที่คนตัวเล็กเข้าถึงกลไกทำงาน ประสานงาน ความเชี่ยวชาญที่จำเป็นต่อการเติบโต โดยไม่ต้องสร้างทุกอย่างเอง

**POSITIONING** — SoloCorp OS สนับสนุนความสามารถมนุษย์ ไม่ใช่แทนที่มนุษย์หรือองค์กรจริงทั้งหมด

### หลักการ 4 ประการ
1. ความสามารถมีอยู่แล้ว แต่ระบบสนับสนุนอาจขาด — เริ่มจากเห็นศักยภาพผู้ใช้ ไม่ใช่ว่าเขาด้อย
2. เอาโครงสร้างองค์กรมาให้เข้าถึงได้ — แบ่งหน้าที่ ส่งต่องาน ประสานงาน ให้คนตัวเล็กใช้ได้
3. ปรับให้เข้ากับผู้ใช้ ไม่บังคับผู้ใช้เข้ากับระบบ — อาชีพต่างกัน สร้างโครง/ผู้เชี่ยวชาญของตัวเองได้
4. เทคโนโลยีต้องเกิดผลจริง — คุณค่าวัดจากงานที่สำเร็จ/ปัญหาที่แก้ได้ ไม่ใช่จำนวน Agent/แผนก

## 3. หมุดหมาย 5 ระดับ (ข้อเสนอเชิงกลยุทธ์ — ไม่ใช่ยืนยันว่าทำเสร็จแล้ว)

| หมุด | ชื่อ | เกณฑ์สำเร็จ |

| 1 | เครื่องจักรกลาง | งาน 1 ชิ้นผ่าน Agent ที่เกี่ยวข้องอย่างเป็นระบบ (ไม่ใช่เรียก AI แยกกัน) |
| 2 | องค์กรเสมือน | ผู้ใช้เห็นว่าใครรับผิดชอบอะไร งานอยู่ขั้นไหน ผ่านตรวจหรือยัง |
| 3 | ผู้ใช้สร้างระบบของตนเอง | ปรับใช้ได้หลายอาชีพ โดยไม่บังคับโครงเดียว |
| 4 | พิสูจน์คุณค่ากับคนตัวเล็ก | ทดลองงานจริง (คาเฟ่/ฟรีแลนซ์/ครู/เกษตรกร) วัดได้: เวลาประหยัด/ผิดพลาดลด/สำเร็จเพิ่ม/ค่าใช้จ่ายลด |
| 5 | ขยายการเข้าถึง | กลุ่มใหม่ปรับใช้ได้โดยไม่ต้องเชี่ยวชาญ AI — คำนึงต้นทุน ใช้งานง่าย ปลอดภัย เหมาะพื้นที่ |

หมุด 1 มีแล้ว (Bus+queue+routing) / หมุด 2 มีโครงแล้ว (19 แผนก) แต่ผู้ใช้นอกยังมองไม่เห็นง่ายๆ /
หมุด 3 คือช่องว่างใหญ่สุด (โครงวันนี้ยังเป็นบริษัทเทคเดียว) / หมุด 4 ยังไม่เกิดเป็นตัวเลข / หมุด 5 รอสนามแรกบอกว่าต้องเบาแค่ไหน

## 4. North Star (เข็มทิศตัดสินใจ)

> **เราไม่ได้สร้างองค์กรเสมือนเพื่อให้คนตัวเล็กต้องกลายเป็นองค์กรขนาดใหญ่
> แต่เพื่อให้คนตัวเล็กมีระบบสนับสนุน ช่วยให้สิ่งที่เขาทำได้ดีอยู่แล้ว สำเร็จได้มากขึ้น**

### ฟิลเตอร์ 5 ข้อ — ทุกฟีเจอร์ใหม่ต้องตอบได้อย่างน้อย 1 ข้อ
1. ช่วยให้งานที่ไม่ถนัดดีขึ้นไหม?
2. ลดงานซ้ำ เพิ่มเวลางานมีค่าไหม?
3. บริหาร/ตัดสินใจเป็นระบบขึ้นไหม?
4. ผู้ใช้ควบคุม ตรวจสอบ เข้าใจระบบได้ไหม?
5. ต้นทุนเหมาะกับคนตัวเล็กไหม?
- ถ้าเพิ่ม Agent/ซับซ้อน/ต้นทุน แต่ไม่ช่วยผู้ใช้บรรลุเป้าหมาย → ทบทวน
- วัดสำเร็จที่ **ขีดความสามารถผู้ใช้เพิ่มขึ้น** โดยเขายังเป็นเจ้าของกิจการ อาชีพ และการตัดสินใจของตัวเอง

## 5. ส่วนที่ตกผลึกเพิ่มใน session 2026-10-15 (CEO ↔ Owner)

### 5.1 OpenExecutive vs SoloCorp — คนละสายพันธุ์ (Owner ตั้ง, CEO รับ)
- **OpenExecutive = สูทสวมบริษัทมนุษย์เดิม** — เจอคนตรง Slack/Gmail/M365, executive voice เดียว, Act as me, episodic memory, scheduler single-instance, API :8000 + `/mcp`
- **SoloCorp = สร้างบริษัทดิจิทัลใหม่ทั้งหลัง** — 19 แผนก + Central Bus :8099 + Loop Runner, เป้าหมายเดินต่อได้โดยมนุษย์ไม่ต้องเฝ้าจอ
- Bridge (HIT + 5 tools) จึงไม่ใช่แค่ API call แต่คือ **protocol ระหว่าง 2 องค์กร**: องค์กรมนุษย์ ↔ องค์กรดิจิทัล
- โมเดลที่กางไว้ (ยังไม่เลือก): A) นาย-บ่าว (HIT ทีละจ๊อบ) / B) มอบอำนาจเป็นรอบ (standing authority + Loop Runner) / C) สนธิสัญญา 2 องค์กร (truth อยู่ที่ไหน)
- **พักไว้ตาม Owner สั่ง:** Budget ledger ยังไม่คิด (รอวันที่จะพัฒนาจริงค่อยวางแผน) / ข้อ 4 Bus-as-a-Service ยังไม่คิด / Trust boundary ยังเปิดไว้

### 5.2 สนามแรกหมุด 4 — ครีเอเตอร์สายสร้างตัวตน (Owner เลือก)
- เหตุผล: คนส่วนใหญ่สนใจ ภาพตามง่าย รอบพิสูจน์สั้น (โพสต์วันนี้เห็นผลใน 7 วัน) ของในบ้านตรงอยู่แล้ว (Sek + Mark + Design) เสี่ยงต่ำ (ไม่แตะเงิน/ภาษี/กฎหมายตรงๆ)
- **เลือกสายสร้างตัวตน ไม่เอาสายขายของ** — สายขายของวัดยาก ผูกปัจจัยนอกคอนเทนต์ อ้างยอดขาย = ขายฝัน ก้ำกึ่งหลอกลวง
- สายสร้างตัวตนวัดซื่อสัตย์กว่า: ความสม่ำเสมอ + ความชัดตัวตน + โอกาสที่เข้ามา (ทักถามงาน/สั่งของ/collab)
- **หลักไม่เป็นทางการข้อ 5:** *SoloCorp ไม่ขายฝันยอดขาย*

### 5.3 นิยามครีเอเตอร์ใหม่ (Owner ขยาย)
- ครีเอเตอร์ ≠ แค่คนทำคลิปหาเงินจากวิว — **เจ้าของร้านเบเกอรี่ทำคอนเทนต์ขยายร้านก็คือครีเอเตอร์** ครูอัดคลิปสอน เกษตรกรไลฟ์หน้าสวน ฟรีแลนซ์เล่างาน — ทุกอาชีพที่ต้องสื่อสารคุณค่าคือครีเอเตอร์
- ผล: สนามแรกกับสนามต่อไปคือสนามเดียวกัน แค่เปลี่ยนชุดคำถามตั้งต้น — template ถูกออกแบบดี reuse ได้ทั้งประเทศ
- ความต้องการ 3 อย่างที่ Owner ระบุ: **ตัวช่วยคิดไอเดีย + ตัวช่วยออกแบบสคริปต์ + เวิร์กโฟลว์ช่วยเดินงาน** (= โครงทีมตั้งต้น ไม่ต้องเดา)

### 5.4 ออนบอร์ดหมุด 3 — ผสม 2 ด้าน (Owner ตัดสิน)
- อย่างเดียวพัง: จัดทีมฟุตบอลอย่างเดียว → งงศัพท์ / ตอบคำถามอย่างเดียว → ไม่รู้สึกเป็นของตัวเอง
- **2 จังหวะ:** (1) ถามเบาๆ 3-4 ข้อ ระบบเดาโครงแรกให้ (2) วางเป็นสนามให้เจ้าของลากเข้าออกเอง — ง่ายตอนเริ่ม เป็นเจ้าของตอนจบ
- โครงตั้งต้นต้องต่างตามสาย: TikTok ขายของ vs YouTube สอน vs LinkedIn สร้างตัวตน ใช้ทีมเดียวกันไม่ได้

### 5.5 โครงเรื่อง 4 ท่อน (CEO ถอดจากคำถาม Owner — ยังไม่ใช่แบบฟอร์ม)
จากคำถาม Owner (เราเป็นใคร/ทำอะไร/ให้ใคร/เพื่ออะไร/อะไรทำให้เป็นเรา/ผ่านอะไรมา/แก้ปัญหาเรายังไง/ช่วยคนอื่นยังไง):
1. **ตัวตน** — เราเป็นใคร + ทำอะไร
2. **รอยแผล** — กว่าจะเป็นแบบนี้ผ่านอะไรมา (ขนมปังก้อนนี้ล้มเหลวมากี่รอบกว่าจะอร่อย — ตัวอย่าง Owner — ท่อนที่คนจำได้สุด)
3. **คนดู** — ตั้งใจให้ใคร + ช่วยเขาได้ยังไง (จากแก้ปัญหาตัวเอง → ช่วยคนอื่น)
4. **เหตุผลที่ยังทำ** — เพื่ออะไร (เหตุผลที่ตื่นมาทำต่อ ไม่ใช่เหตุผลที่ขายได้)
- สายขายของเล่าแต่ท่อน 3 / สายสร้างตัวตนเล่าครบ 4 ท่อน คนดูเลยรักไม่ใช่แค่ซื้อ
- ท่อน 2+3 คือสะพานเชื่อมคน 2 กลุ่มตามวิสัย Owner

### 5.6 ขนมปัง + น้ำ — ธาตุประจำระบบ (Owner อุปมา, CEO รับเป็นหลัก)
- riddle ขนมปัง **ตั้งเป๊ะๆ ไม่ได้** — ยืดหยุ่นตามสถานการณ์ มุมมอง mindset ช่วงเวลาของแต่ละคน
- อุปมาน้ำ: ไหลได้ นิ่งได้ เย็นได้ ร้อนได้ แข็งได้ ระเหยได้ เป็นเพชฌฆาตก็ได้ เป็นผู้ช่วยชีวิตก็ได้
- ระบบที่ดีต้องเป็น **ภาชนะ ไม่ใช่แม่พิมพ์** — รับได้ว่าวันนี้น้ำมาแบบไหน (เล่าตลก/ซึ้ง/ไม่เล่าแค่ถ่ายมือ) ไม่ดัดคนเล่าให้ตรงระบบ
- คำถามตั้งต้นต้องเป็นคำถามแบบน้ำ (เปิด) ไม่ใช่แบบหิน (ABCD) / ทีมต้องเป็นทีมแบบน้ำ (รวมแยกได้ตามชีวิต) ไม่ใช่แบบตึก
- AI + คอนเทนต์เหมือนน้ำ: ใช้ดีหล่อเลี้ยง ใช้ผิดท่วม — ที่เลือกสายสร้างตัวตนคือเลือกเป็นผู้ช่วยชีวิตตั้งแต่ก่อนเริ่ม
- **วิธีใช้:** เวลาตัดสินใจอะไร ถามว่า *แบบนี้ไหลตามผู้ใช้ไหม หรือกำลังบังคับให้ผู้ใช้เป็นหิน?*

### 5.7 เชื่อมคน 2 กลุ่ม (วิสัย Owner — เก็บไว้ ไม่ตกผลึก)
- กลุ่ม 1 = คนตัวเล็กที่มีของดีแต่คนไม่เห็น / กลุ่ม 2 = คนที่มองหาของดีนั้นแต่หาไม่เจอ
- คอนเทนต์ = สะพาน, SoloCorp = คนสร้างสะพาน → ใหญ่กว่าเครื่องมือทำคลิป คือ **ตลาดการมองเห็น** ที่ไม่ต้องจ่ายแอดแพงก็เจอกันได้
- ทางแยก (ยังไม่เลือก): ช่วยแค่ฝั่งสร้างแล้วปล่อยแพลตฟอร์มจับคู่ / หรือวันนึงช่วยจับคู่เองด้วย
