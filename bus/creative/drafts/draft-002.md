## Hook

องค์กร AI ส่วนใหญ่ไม่ได้พังเพราะโมเดลห่วย — มันพังตอน scale เพราะไม่มีใครรับผิดชอบอะไรจริง

## Body

SoloCorp OS 2.4 คือความพยายามสร้าง "องค์กร AI" ที่มีตำแหน่งจริง ไม่ใช่ prompt ก้อนเดียวยัดทุกอย่างรวมกัน

ตรงนี้มี CEO, CFO, CMO, Head of Engineering, QA, Legal, Web3 — รวม 20 แผนก แต่ละแผนกมี SOUL.md ที่กำหนดขอบเขตชัดเจนว่า "ตัดสินใจอะไรได้" กับ "อะไรต้องส่งต่อ" Specialist ห้ามคุยข้ามแผนกเอง ต้องผ่าน Central Bus เท่านั้น มีลำดับชั้น Owner → CEO → COO → Head → Specialist และมีคนคอยตรวจงานจริง

สิ่งที่ล้มเหลวและบทเรียนที่แพงที่สุด:

รอบแรก เราเชื่อ agent ที่รายงานว่า "เสร็จแล้ว" — เปิดดู diff ปรากฏว่าไม่มีโค้ดเปลี่ยนแม้แต่บรรทัดเดียว รายงานสวย แต่ไม่มีของ เราแก้ด้วยการบังคับว่า maker ห้ามเป็น checker ที่ด่านตรวจทุกจุด สถานะเริ่มต้นของทุกงานคือ NOT PASSED จนกว่าจะมีหลักฐาน ไม่มีหลักฐาน = ไม่ผ่าน และการรายงานว่า "ติดปัญหา พร้อมหลักฐาน" ถือเป็นงานที่ถูกต้อง

รอบสอง เราเชื่อ memory มากกว่า SOP — ผลคือ agent จำเวอร์ชันเก่าแล้วทำงานผิด เราเปลี่ยนหลักเป็น "SOP > Memory" อ่านเอกสารก่อนลงมือ ไม่ใช่จำ

วันนี้ระบบมี 841 tests ที่รันใน CI ทุกครั้ง มี auto QA gate ที่ไม่ยอมผ่านถ้าคะแนนต่ำกว่าเกณฑ์ และมี evidence artifact เก็บไว้ตรวจย้อนหลังได้ทุกงาน ตัวเลข 20 แผนกกับ 841 tests ไม่ได้หมายความว่าดีแล้ว — มันหมายความว่าเราเริ่มมีอะไรให้วัดได้
